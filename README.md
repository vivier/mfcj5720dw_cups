# Brother MFC-J5720DW CUPS driver

An independent native CUPS driver for the Brother MFC-J5720DW, developed by
reverse engineering the original Brother printing pipeline. It converts
CUPS Raster directly into printer data and retrieves ink levels and factory
printhead calibration through the CUPS side channel. The encoder is linked
into the filter, so no Brother LPR command or wrapper is needed.

The [printer protocol specification](PROTOCOL.md) describes this model's
command stream, binary fields, raster and JPEG framing, duplex, maintenance
and status queries. It includes annotated captures and public references,
and distinguishes code-derived behavior, physical tests and remaining unknowns.

## Requirements

Build on Linux with GCC, GNU Make, CUPS development headers and PPD tools,
libjpeg development headers, and Python 3.11 or newer. RPM packaging also
needs `rpmbuild`, `rpmspec`, binutils, `file`, groff, tar and gzip.

On Fedora, the build dependencies are:

```sh
sudo dnf install gcc make cups cups-devel libjpeg-turbo-devel python3 \
    rpm-build binutils file groff-base tar gzip grep coreutils
```

The build targets the host architecture and puts binaries in `build/`.
The current encoder retains x86/x87 and little-endian assumptions; the RPM
spec supports x86_64 and 32-bit x86. The x86_64 build needs no 32-bit
compatibility libraries. Keep the supplied compiler flags: they preserve
the encoder's current arithmetic and data-layout behavior.

## Build

```sh
make -j4
make check-static
```

The resulting files are:

- `build/rastertomfcj5720dw`: the CUPS Raster printing filter;
- `build/mfcj5720dw_ink`: the ink-level reporting filter and command;
- `build/commandtomfcj5720dw`: the maintenance command filter;
- `ppd/mfcj5720dw.ppd`: the generated printer description;
- `lut/*.BCM`: the ten generated color calibration profiles.

`make check-static` checks the PPD, manpage formatting, encoder header
interfaces and ELF metadata. It does not send a print job or contact a
printer, and it does not replace a hardware printing test.

The source tree is self-contained. It requires no other checkout, original
Brother RPM, decompilation tool or downloaded calibration files.

The PPD includes English and French labels for options, choices, paper sizes
and ink colors. CUPS selects the appropriate labels for the application's
locale. Edit `fr.po` to update the French translation, then run `make ppd`.
The source RPM includes this catalog; translations are embedded in the
installed PPD and require no separate runtime package. Existing queues retain
their own PPD copy and must be updated to use the translated PPD; recheck
queue defaults after replacing it.

## Color enhancement controls

In **Color Settings (Advanced)**, enable **Color Enhancement** to use the image
adjustments. **Color Density** and **White Balance** each have five levels,
from **-2** through **+2**, with **0** as the default. Color Density adjusts
color intensity; White Balance adjusts the correction of color casts in light
areas. Zero retains the existing enhancement behaviour, including its automatic
white-balance correction. It does not disable that correction.

The two controls apply only to color output with enhancement enabled, before
both raster and JPEG encoding. They are independent of factory printhead
calibration and ink-level reporting. Brightness, contrast and RGB controls
continue to work as before. For example:

```sh
lp -d PRINTER -o BRColorEnhancement=ON -o BRColorDensity=1 \
  -o BRWhiteBalance=-1 document.pdf
```

French labels are **Densité des couleurs** and **Balance des blancs**. Existing
queues need their PPD updated to show the new controls. Older PPDs remain
compatible and keep both settings at zero.

## Custom paper sizes

Custom sheets can be 88.9–287 mm wide and 127–431.8 mm long. These limits
follow Brother's Windows user-defined size range. All four hardware margins
are 9 points (3.175 mm), matching the driver's ordinary paper margins.
Custom sizes support simplex printing with Auto Select or MP Tray; load the
paper in the MP tray. Duplex and borderless printing require a supported
named paper size.

In applications that offer custom page setup, enter the sheet dimensions
there and select the Brother MFC-J5720DW CUPS queue. From the command line:

```sh
lp -d PRINTER -o PageSize=Custom.100x150mm -o BRInputSlot=MPTray \
   -o Duplex=None document.pdf
```

CUPS also accepts inches (`Custom.4x6in`) or points (`Custom.288x432`).
Dimensions describe the unrotated sheet; select landscape separately in the
application. The encoder retains automatic landscape feeding for custom
sheets 127–215.9 mm wide and longer than 215.9 mm, up to approximately 297 mm.
Load those sheets with their long edge entering the printer; other custom
sheets use short-edge feeding. This transport rotation is independent of
the document's portrait/landscape layout.

The filter preserves fractional dimensions and CUPS' raster rounding. It
rejects out-of-range sheets, incompatible trays or duplex, and rasters whose
sheet size or printable area disagrees with the job. Pages in one job must
use the same dimensions. Update both the filter and an existing queue's PPD
to enable custom sizes. The implementation has been checked in the VM with
PDF rendering and captured output, but custom stock has not yet been tested
on the physical printer.

## Borderless printing

Select a borderless paper size and print at actual size (100%). The driver
applies a paper-specific enlargement so the image extends beyond the sheet:
2.35% for A4, for example. Content near the edges is cropped intentionally;
a 10 mm border drawn in an A4 document leaves about 8 mm at each side and
6.5–7 mm at the top and bottom. Keep important content away from those edges.

The filter uses bilinear interpolation after upstream rendering, avoiding a
Ghostscript 10.06 positioning defect that introduced a white strip at the top
and clipped the bottom when using its standard borderless scaling factor.
Physical paper size and enlarged image dimensions remain separate.

A4 includes a measured 1.5 mm downward placement correction within the
overspray area. This adjustment preserves the enlargement and horizontal
position. Full coverage and centered placement were confirmed on A4 plain
paper; the other paper sizes retain their original placement. The factors
and placement values are defined in `mfcj5720dw.drv`.

Existing queues must update their PPD to use these changes; reinstalling the
RPM updates the model PPD but preserves each queue's own copy. Re-select the
driver for the queue and review its defaults, as described below for maintenance.

## Build RPM packages

```sh
make rpm             # Source RPM and native binary RPM
make srpm            # Source RPM only
make rpm-sources     # Source archive and spec only
```

Packages are written to `build/rpm/RPMS/<architecture>/` and
`build/rpm/SRPMS/`. The source archive contains the build sources, XML
profiles and notices. The binary package installs three filters, the PPD,
generated BCM profiles, three manpages and license/provenance notices.

For an x86_64 Fedora build, installation is:

```sh
sudo dnf install ./build/rpm/RPMS/x86_64/mfcj5720dw-cups-*.x86_64.rpm
```

CUPS, cups-filters and Ghostscript are runtime dependencies of the package.
Add the printer in the desktop printer settings or CUPS administration
interface and select **Brother MFC-J5720DW CUPS**. For network printing, a
JetDirect connection uses `socket://PRINTER_IP:9100`; replace `PRINTER_IP`
with the printer's address.

Final RPM removal deletes local CUPS queues using any of this driver's
filters. Upgrades and reinstalls preserve the queues and their settings.

## Install without RPM

```sh
sudo make install
```

The default prefix is `/usr`. `PREFIX`, `CUPSFILTERDIR`, `PPDDIR` and
`DATADIR` can be overridden. For a staged installation:

```sh
make install DESTDIR=/tmp/mfcj5720dw-install
```

After installation, `man rastertomfcj5720dw`, `man mfcj5720dw_ink` and
`man commandtomfcj5720dw` describe the printing, ink-level and maintenance interfaces.

## Maintenance

The driver advertises `Clean`, `PrintSelfTestPage`, `ReportLevels` and two
cleaning extensions as CUPS commands. All cleaning commands take exactly one
ink selection: `all`, `black` or `color`.

| CUPS command | Cleaning strength | Printer operation |
| --- | --- | --- |
| `Clean` | Normal | `NORMALPURGE` |
| `CleanStrong` | Strong | `POWERPURGE` |
| `CleanStrongest` | Strongest | `SUPERPOWERPURGE` |

The additional cleaning commands are defined by this driver.
Stronger modes consume more ink. `PrintSelfTestPage` prints the internal nozzle-check sheet;
it is distinct from the ordinary CUPS document test page.

For example, replace `PRINTER` with the queue name:

```sh
printf '#CUPS-COMMAND\nPrintSelfTestPage\n' | \
  lp -d PRINTER -t 'Nozzle check' -o document-format=application/vnd.cups-command
```

GNOME's head-cleaning action submits `Clean all`. An existing queue must use
the updated PPD to expose that action; updating the installed model PPD alone
does not update the queue's private copy. Re-select the driver for that queue,
or use `sudo lpadmin -p PRINTER -m Brother/mfcj5720dw.ppd` and review its defaults.
The other ink selections and strengths are available through command jobs;
GNOME does not add buttons for these extensions. For example:

```sh
printf '#CUPS-COMMAND\nCleanStrong black\n' | \
  lp -d PRINTER -t 'Strong black-head cleaning' -o document-format=application/vnd.cups-command
```

The filter validates the complete job before sending anything, then leaves
transport and job ordering to CUPS. It does not poll for physical completion.
See [commandtomfcj5720dw(1)](commandtomfcj5720dw.1)
for command syntax, limits, ink reporting and examples.

Printhead alignment is still performed on the printer's touchscreen, using
Settings → Maintenance → Improve Print Quality → Alignment. Choose the paper
size and follow the on-screen pattern selection. See
[Brother's alignment procedure](https://support.brother.com/g/b/faqend.aspx?c=us&faqid=faq00000259_027&lang=en&prod=mfcj5720dw_us_eu_as).
The inspected Windows and macOS drivers did not establish a remote calibration
protocol. Their vertical-line rendering options are separate from this procedure;
`PrintAlignmentPage` and `SetAlignment` are therefore not advertised.

## Printhead calibration

The **Printhead Calibration** option controls nozzle and density corrections
specific to the physical printer. These complement the model and paper profiles
in the BCM files; they are separate from ink-level reporting and ICC profiles.

| Choice | Behavior |
| --- | --- |
| **Automatic** (`BRCalibration=Auto`) | Use cached calibration, or retrieve it when none is available. This is the default. |
| **Refresh Before Each Job** (`BRCalibration=Refresh`) | Retrieve a fresh snapshot before every job while selected. |
| **Disabled** (`BRCalibration=Off`) | Use the model profiles without per-printer corrections. |

For a one-time refresh, pass `-o BRCalibration=Refresh` to `lp` for that job.
Queues created with an older PPD also default to Automatic in the filter;
update their PPD to expose the new choices in the print dialog.

Retrieval uses read-only SNMP queries through the CUPS backend and requires
a backend with SNMP support and network access to the printer. It has an
eight-second budget, separate from ink polling. A failed reading retains a
valid cached snapshot or falls back to the model defaults. It does not prevent
printing or run a cleaning or alignment operation.

Complete snapshots are cached per queue and device URI in `CUPS_CACHEDIR`
(normally `/var/cache/cups`) as `mfcj5720dw-*.calibration`, with permissions
`0600`. Credentials are excluded from the cache identity, and replacement is
atomic. If the directory is unwritable, a successful reading still applies to
the current job. Select Refresh when replacing a physical printer at the same
URI. Cache files have no periodic expiry and are not purged on package removal.

The encoder holds one snapshot for the job, loads all eleven density banks
and rebuilds nozzle thresholds for each page. Corrections apply to supported
raster modes; host-side JPEG transfer bypasses these threshold calculations.
See `man rastertomfcj5720dw` for the option and environment details.

## Calibration sources

Edit `lut/*.xml` and the shared tables in `lut/cubes/` and `lut/curves/`,
then run `make profiles`. These descriptions use IccXML's structure with
Brother-specific elements in the `urn:brother:bcm:1` namespace.
`lut/bcm_from_text.py`, `bcm_text.py` and `bcm_xml.py` compile them using only
the Python standard library. Python is a build dependency, not a runtime
dependency of the installed filters.

Each color cube has 17 × 17 × 17 RGB grid nodes, with four C, M, Y, K values
per node. In `TableData`, blue varies fastest, then green, then red. Comments
label the coordinates; the order of the numbers defines the data. Other
blocks expose named curves, halftone parameters and correction factors.
The unedited XML sources reconstruct the original BCM files byte for byte.

The 72 cube blocks share 42 tables in `lut/cubes/`. The 225 individual curves
use 61 nonconstant tables in `lut/curves/` and 100 zero-filled curves described
by `Constant="0"`. Each profile keeps its ink limits, curve names and tag IDs:

```xml
<bcm:CubeType Source="cubes/cube-001.xml" />
<bcm:Curve Name="cyan_transfer" Source="curves/curve-001.xml" />
<bcm:Curve Name="cyan_offset" Constant="0" />
```

Paths are relative to the profile file. Shared filenames are stable
identifiers; comments record the original BCM profiles, tags and curve
names. A shared cube file contains a complete `bcm:CubeType` with `Channels`,
`CLUT` and `TableData`. A shared curve file has a `bcm:Curve` root containing
256 integers, without a `Name` attribute. The referring curve name selects
its binary slot and signedness: the four offset curves use s16, while the
transfer and monochrome-black curves use u16.

`Constant` generates 256 identical samples and accepts any integer within
the named curve's range. `Source`, `Constant` and inline sample values are
mutually exclusive. References use local `cubes/<name>.xml` or
`curves/<name>.xml` files; paths outside the profile directory and nested
references are rejected.

Editing a shared table affects all its users. To edit one independently,
copy the table and change that reference. `make profiles` tracks changes to
both shared directories, and source RPMs include them. The BCM exporter
`lut/bcm_to_text.py` writes standalone XML with inline tables and compact
`Constant` values; the compiler accepts both standalone and shared sources.

The converter generates the fixed bytes shared by the original profiles;
they no longer appear as `bcm:Opaque` elements in XML. Importing a BCM file
with different fixed bytes or nonzero reserved header bytes fails explicitly.
Older XML descriptions containing `bcm:Opaque` are no longer accepted.
